# Langages, protections et limites

## Langages gérés

| Famille | Extensions | Particularités traitées |
|---|---|---|
| JavaScript / TypeScript | `.js .mjs .cjs .jsx .ts .mts .cts .tsx` | regex littérales, template literals et leurs `${}`, `{/* */}` JSX |
| Web | `.html .htm .xml .svg .vue .svelte` | découpage `<template>` / `<script>` / `<style>` |
| CSS | `.css .scss .sass .less` | pas de `//` en CSS pur, `//` en SCSS/LESS |
| Python | `.py .pyi .pyw` | docstrings distinguées des chaînes assignées ou passées en argument |
| PHP | `.php .phtml` | HTML hors `<?php ?>`, heredoc et nowdoc |
| Go | `.go` | chaînes brutes entre accents graves |
| Rust | `.rs` | `r#"…"#`, blocs imbriqués, `'a` durée de vie ≠ `'a'` caractère |
| JVM / .NET | `.java .kt .kts .scala .cs .dart` | blocs de texte `"""` |
| C / C++ / ObjC | `.c .h .cpp .cc .cxx .hpp .m .mm` | |
| Ruby | `.rb .rake Gemfile Rakefile` | `=begin` / `=end` |
| Swift | `.swift` | blocs imbriqués |
| SQL | `.sql` | `''` échappé, `--` nécessitant une espace |
| Shell | `.sh .bash .zsh .env` | heredocs cités et non cités, `#` en milieu de mot |
| Config | `.yml .yaml .toml .ini .cfg .conf Dockerfile Makefile` | scalaires bloc YAML `\|` et `>` |
| Lua | `.lua` | `--[[ ]]` |

Une extension absente de cette liste fait ignorer le fichier, avec une mention dans
le rapport. Le script ne devine jamais la syntaxe d'un langage inconnu.

## Toujours exclus

`node_modules`, `vendor`, `dist`, `build`, `.next`, `__pycache__`, `.venv`, `target`,
les fichiers minifiés et générés (`.min.js`, `.pb.go`, `_pb2.py`, `.g.dart`), les
liens symboliques et tout fichier au-delà de 1 Mo.

## Protections reconnues

**Directives outils** — `eslint-disable*`, `eslint-env`, `tslint:`, `stylelint-disable`,
`@ts-ignore`, `@ts-expect-error`, `@ts-nocheck`, `@flow`, `$FlowFixMe`,
`prettier-ignore`, `biome-ignore`, `dprint-ignore`, `deno-lint-ignore`,
`@formatter:off`, `istanbul ignore`, `c8 ignore`, `sourceMappingURL`, `webpack*:`,
`@vite-ignore`, `noqa`, `type: ignore`, `pylint:`, `mypy:`, `pyright:`, `ruff:`,
`flake8:`, `isort:`, `fmt: off`, `nosec`, `pragma: no cover`, `noinspection`,
`#pragma`, `#region`, `NOLINT`, `clang-format off`, `SuppressWarnings`, `NOSONAR`,
`swiftlint:`, `go:build`, `+build`, `go:generate`, `go:embed`, `nolint`, `rubocop:`,
`frozen_string_literal:`, `phpcs:`, `@phpstan-`, `@psalm-`, `@codeCoverageIgnore`,
`shellcheck disable`, `hadolint`, `yamllint`, `gitleaks:allow`, `nosemgrep`,
`trivy:ignore`, `tflint-ignore`, `checkov:skip`, `vim: set`, `-*- coding -*-`,
`DO NOT EDIT`, `@generated`, `Code generated by`, et tout bloc ouvrant par `/*!`.

**En-têtes** — shebang, déclaration d'encodage, et tout commentaire des huit
premières lignes contenant `copyright`, `SPDX-License-Identifier`, `licence`,
`all rights reserved`, `@license`, `@preserve`.

**Marqueurs** — `TODO`, `FIXME`, `HACK`, `XXX`, `BUG`, `NOTE`, `OPTIMIZE`, `REVIEW`,
`REFACTOR`, `DEPRECATED`, `WARNING`, `IMPORTANT`, `CAUTION`, `SAFETY`, `SECURITY`
en majuscules, ou `todo:` / `fixme:` / `hack:` / `bug:` suivis de deux-points.

**Documentation d'API** — docstrings Python, blocs `/** */`, lignes `///` et `//!`.

## Limites connues

- Une regex JS placée juste après une parenthèse fermante (`if (x) /re/.test(y)`)
  est lue comme une division. Cas rare ; au pire un commentaire n'est pas détecté.
- Les f-strings Python n'ouvrent pas de zone de code : un commentaire à l'intérieur
  d'une expression `{}` d'une f-string n'est pas détecté.
- Un fichier `.html` avec un `<script>` non fermé bascule en règles HTML jusqu'à la fin.
- Les commentaires imbriqués ne sont gérés que pour Rust et Swift, seuls langages
  de la liste où ils sont légaux.

Toutes ces limites échouent du côté sûr : le commentaire n'est pas détecté, donc
pas modifié.
